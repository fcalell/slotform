# Roster

The component contract both UI plugins ship to: the canon of names and closed props, the descriptors a
composed region is made of, the roster that lists every component as data, the variant matrices and
single class sets a component draws, the shared shapes of a button, a status, a chip, a fact and a change
mark, and the `DESIGN.md` emitted from all of it. The layout parts are in [layout](layout.md), the
reads they draw in [reads](reads.md), the acts in [acts](acts.md), and each content molecule in
[components](components.md).

## The canon and the closed props

The canon binds every component either plugin ships:

- One name per concept: `label`, `onChange`, `onAct`, `act`, `blocked`, `sentence`, and the words
  `docs/architecture/conventions.md` lists (`facts`, `line`, `warning`, `lock`, `leading`, `status`,
  `chip`).
- A composed region is a typed descriptor (`Act`, `StatusMark`, `ChipMark`, `Fact`, `RecordFact`,
  `RowLeading`, `RowTrailing`, `PlaceSpec`, `Option`, `FieldBinding`, `TableColumn`, and the rest of
  [descriptors](#descriptors)), never a node region.
- No `class`, `className`, `classList` or `style` prop. A look a component does not offer is a matrix
  class set or a consumer primitive ([Tailwind reset](tokens.md#tailwind-reset)).
- An icon is an `IconName`, a closed type over Lucide's glyph names by their PascalCase name (`Check`,
  `ChevronDown`), the key both `lucide-react` and `lucide-react-native` export it under; Lucide's own
  aliases are names too. Each plugin draws a name from one table built over its platform package,
  which fails the build if a name is missing.

`src/icon-name.ts` is generated by `pnpm --filter @slotform/ui-core icon-name` (`scripts/icon-name.ts`)
as a literal union, so `IconName` needs no Lucide types: ui-core ships the names, not the icon set. A
package that draws a glyph (react-ui, native-ui) depends on Lucide itself, and a server that only
reads ui-core's descriptors installs none of it. `src/icon-name.test.ts` holds the file to the
installed Lucide. The generated file is never edited by hand.

A descriptor is generic only in a value, which is data. A route a descriptor carries is a `Route`,
which reads `RouteRegistry`, an empty interface a platform fills by declaration merging: native-ui
registers expo-router's `Href`, and unregistered a route is any string. So no descriptor takes a route
type parameter, there is no native-only copy of the descriptors, and a control takes its `value` and
`onChange` as props, never optionally from a field context.

## Descriptors

A composed region is data, framework-free, so the owning molecule renders it.
`@slotform/ui-core/descriptors` re-exports every descriptor: one a single component takes is declared
in its `roster/<component>.ts`, one several take in `roster/descriptors.ts`. Why the rows a
collection draws are data is [rows are data](../../decisions/rows-are-data.md); why the roster is
public is [public roster](../../decisions/public-roster.md).

## The roster

The roster is data: `packages/ui-core/src/roster.ts` (`rosterEntries`) names every component both UI
plugins ship, in four layers (`atom`, `layout`, `shared`, `content`), with the prop names it takes,
the class sets it draws, the tokens it owns, the moves it makes and the states it has, the same in both
plugins. An entry with `platforms` ships on those alone (`Canvas` is web only). `DESIGN.md` is emitted
from it, and the showcase draws each component in exactly the class sets and states its entry lists
([showcase](showcase.md)). A component's directory is its name in kebab-case. A component draws
another's place by composing it, never by spelling its class sets.

### Roster entries

An entry holds:

- the component's prop names;
- the class sets it draws: a `MATRIX_GROUPS` name for every class set of that group, `GROUP.axis.value` for one of
  its class sets, or a single-class-set constant of `./variants`;
- `draws`, the matrix groups and constants of its own box ([matrices](#matrices));
- `motion`, the moves it makes ([moves and move class sets](motion.md#moves-and-move-class-sets));
- the states it has a form for, of the closed set `STATES` (`roster/shared.ts`): the interaction
  states, `empty` for a component with an empty shape, and the states a read puts a frame or
  collection in;
- the tokens it owns ([token ownership](#token-ownership)).

### Token ownership

An entry names the tokens its component may draw, by namespace: type roles, colours, radii, spacing
roles, sizes and widths, shadow elevations. A colour is a name, or a family prefix ending in `-` (`chip-`
covers every chip role); every other namespace names its tokens. A namespace left out owns nothing.

### Roster files

Each entry is declared in its component's `src/roster/<component>.ts`, beside the descriptors,
matrices, cvas and class sets that component alone uses; `roster.ts` groups them by layer. `variant-tables.ts` declares the matrices two or more components share; `roster.ts`,
`descriptors.ts` and `variants.ts` declare what is shared and import the component files to re-export the rest, so the subpaths keep their
names. A component file therefore takes what it shares from `roster/shared.ts` (values and types,
`RosterEntry` among them) or `roster/descriptors.ts` (the descriptors two or more components take,
`RouteRegistry` among them), never from the four, and no ui-core file is in an import cycle.

## Matrices

The variant matrices are declared as data in `variant-tables.ts` (internal, no subpath) and `build`
makes each cva from its matrix. A cva hides its config at runtime, so the `DESIGN.md` emitter walks the
same object the cva reads, and no enumeration can drift from the matrix it describes. The matrices two
or more components draw are declared there; one component's own stand in its `roster/<component>.ts`,
beside the cvas built from them, and are re-exported. `MATRIX_GROUPS` registers every matrix by table name
with its axes, and `matrixClasses` enumerates the class sets (`BUTTON.act.primary`); the showcase reads the
list.

- A matrix holds platform-invariant class sets only, classes both a web and a native renderer take
  ([the sharing line](../ui-core.md#the-sharing-line)).
- What a component is given (act, family, checked, error) is an axis; where the pointer or focus is on
  it is an overlay.
- A part with an axis is a matrix; a part with one shape is a named constant (`POPOVER`, `PAGE_HEAD`).
- A molecule draws an atom by composing it, never by spelling its class sets; a composed molecule draws its
  own class sets and the composer owns none of them. A class set no entry holds is shared and spelled by each
  component that draws it; an entry's `draws` lists the matrix groups and constants of its own box.
- No class set holds an arbitrary value.
- Heights are floors, never fixed: a minimum height is the floor of something pressed (control, field,
  target, chip, row). An element a pointer lands on is the target
  ([sizes](tokens.md#sizes-and-hit-target)), so a smaller drawn box stands in a target-sized box
  pulled back by the difference (`REMOVE_HIT`). A part beside a line of text is that line's box
  (`LINE_BOX`). Stacking between components is the token `STACK_ORDER`
  ([layers](tokens.md#layers-and-shadows)). A long unbroken word never widens a page.

## Variants

`variants.ts` is the public matrix layer: one cva per table, the axis types a component declares its
props with, the single-class-set constants and `MATRIX_GROUPS` with its class set enumeration. The tables stay
internal. What one component alone draws is declared in its `roster/<component>.ts` and re-exported
here; a motion class set is spelled beside the matrices that compose it and read from here
([moves and move class sets](motion.md#moves-and-move-class-sets)).

`build` is the only way a cva is built. It takes the whole matrix, which leaves no second argument to
get wrong, so a cva cannot render another table's class sets or drop its own base. cva's own config and prop
types are conditional on a concrete axis set, which is why one generic helper widens both.

A variant's props are one optional pick per axis, plus the `class` or the `className` a caller merges
in, never both. The shape is cva's own, spelled in `roster/shared.ts` so the declarations the package
emits name its own types alone: cva keeps its prop types in a `types` module the emit would otherwise
import by path, which is not portable and fails wherever the package is built inside a pnpm virtual
store.

## Class sets

- The type role is the only way to set type; its ink, family and figures ride with it (`TEXT`). Every
  class set is spelled out: Tailwind reads source text, so a class set built from a template compiles to nothing
  in a consumer build.
- The tint a plugin hands to its own glyph or spinner is read back off a class set's colour, since the
  matrices already carry it; it is never written a second time. `toneOf(classSet)` (`./variants`) reads
  it: the first contract colour a `text-`, `bg-` or `border-` class names, else `ink-body`.
- `PRESS_WASH` (`./variants`) is the wash a pressable web surface takes under the pointer and while
  pressed (`hover:bg-wash-hover active:bg-wash-press`): one class set for every row, cell, figure and
  quiet act that washes, the web's overlay held where both its washes are said once.
- Space is a margin on a box that draws, never an empty element: a picker's grouped children stand in
  past the box by the box's width (the group's margin) and the gap after it (the body's).

## Controls

A button's `act` is its kind:

- `primary`: the accent fill, one per screen;
- `danger`: the danger fill, a confirm's one filled act;
- `secondary`: a hairline with no fill;
- `destructive`: the hairline with its label in `danger`;
- `quiet`: words in the meta ink with no fill and no hairline (a resend, a skip).

`fit` is its container's: a control on its own, or full width at a field's height under the field it
submits. A button takes `min-h`, never `h`, so the label can grow the control under OS font scaling.
The fill carries the act's ink for the web's glyph and spinner (`currentColor`); the label repeats it,
since a native `Text` inherits none.

## Status and chips

`tone` is the one vocabulary of tone (`TONES`): a status's mark, a banner's ground and glyph and a
toast's glyph name it. `running` draws a spinner where a status has a mark; `idle` is the hollow dot.

A **status** is its tone's mark (the dot, the running dots) beside its word, the one shape of a status
everywhere: a fact, a row's title, a table cell, a canvas node. A row's or a pick option's leading is
the dot alone, named by its word. A row's facts may hold several statuses, the first leading the line.

A **chip** is a data value's tag: an outlined pill on the surface with a dot in its family's hue, so the
family is learnable across screens and never mistaken for a status. It is the one shape of a chip
everywhere: a fact, a table cell, a picker option, a toolbar's applied filter.

- `ground` is what the box stands on. `edge` is the surface under the hairline every outlined control
  shares, for a hued family. `soft` is the neutral family's soft ground (the one a neutral type mark,
  `ROW_MARK`, stands on), with no edge and no dot.
- The neutral family has no hue and no dot class set: a grey dot on it reads as the `waiting` state's
  filled one (and a hollow one as `idle`'s), one mark with two meanings on a screen that holds both. A
  dotless outlined box is a control's form, a compact one a toggle button beside a row's switches. Its
  soft ground keeps it a tag and apart from a state pill, which is opaque, edged and led by its dot (a
  grey dot is a state's, `STATUS_DOT`).
- The neutral chip is the one look of a neutral word: a record head's plain fact (a word, a count, an
  age) is this pill too, so the head's outlined pills are the facts that act.
- A chip has no height of its own: it is its caption line between its hairlines, the soft ground's
  edge drawn clear so both grounds stand at one height. `trailing` is what closes its right end: its
  own padding, or the remove act's round disc.
- The dot is the family's strong colour. The box carries the ink for the web's remove glyph; the label
  repeats it, since a native `Text` inherits none.

## Facts

A **fact** (`Fact`) is one thing a list says of a thing, in the order given. Every list of facts holds
these kinds (a row's `facts`, a message detail's row, a record head's `facts` among its own):

- words (`Run`, one fact each, a string's own middle dot no part of it);
- a status;
- a chip;
- what is wrong (`{ warning }`);
- a boolean mark.

The kinds are told apart by the keys their members carry, so a fact needs no tag. `splitFacts`
(`@slotform/ui-core/list-state`, with `isStatusFact`, `isWarningFact`, `isChipFact`, `isMarkFact`) is
the one reading of a list; a component's drawing takes its facts through it. It hands back `facts`,
every fact the line draws in the order given, each a `FactPart` tagged with its `kind` (`status`,
`warning`, `chip`, `mark` or `words`), and `quiet`, the boolean marks whose words are not drawn
(`wordless`: `words: false`), which stand in the row's end group. A ring that does not hold says no
fact (`says`) and is in neither. A list may hold several statuses, each its own badge with its tone
mark; the first leads the line, and the row's lock follows it.

Each plugin reads a list of facts as the badges a line draws, free of any view, so a test holds its
structure: the row, the record head and the picker's option draw from it. Each fact is one badge, in
the order given; the badge says what it draws (`kind`), the words it reads as (`name`, the accessible
name, which is also the full text a cut badge keeps) and, where it is painted, no words at all.

## Marks

`ChangeKind` is where a record, a row or a field stands in a change set: `added`, `changed`, `removed`,
`unchanged` (so a marked set lines up) or `stale` (the change set does not match what it was made
against). One mark draws it on every part that carries a `change`.

A glyph means one thing, so no mark's glyph is an act's or a state's:

- A change mark's glyph is drawn by kind and named by the kind's own word. `added` and `removed` are
  the boxed plus and minus a diff's file marks are, never the bare plus of an add act standing on the
  same screen, nor a circle that reads as a picked radio beside a list's kind.
- The back act's glyph is an arrow, on every platform and at every density. A chevron says "opens
  here" and an arrow "leads elsewhere"; a back chevron would say a second thing with the fold's glyph.

## Popups and cut text

- A popup trigger renders the icon act's base (`IconButtonBase` in react-ui's `atoms/button/glyph.tsx`);
  the icon act's base names the act with a Tooltip, none on touch.
- Text a part cuts names itself through one shared tooltip the container host mounts
  (`shell/cut.tsx`), shown only when it measures cut.
- No popup of the roster locks the page scroll (`Picker` passes `modal={false}`); a sheet is modal by
  design.
- Menu and Picker call `useQuietGuards` (react-ui's `lib/guards.ts`), which takes `aria-hidden` off
  Base UI's focus-guard spans, so an open popup audits clean while the Tab relay holds. The guards
  otherwise keep Base UI's own markup: no `tabindex="-1"`, no role, no patch.

## Structure rules

The structure rules (`packages/ui-core/guide/structure.md`) apply to the whole roster: a parent lays
out with flex or grid and a child says only how it flexes; nothing reads its children, and no
framework context changes a child's form. Every `createContext` is classed `data`, `behaviour` or
`portal`. `ShellHome` is the one named `form` exception, and `DistanceContext`, the room set, the
other: a designed density tier no media query detects ([the room](tokens.md#the-room)).

## DESIGN.md

The package's `DESIGN.md` is the contract in the
[DESIGN.md format](https://github.com/google-labs-code/design.md), version `alpha`: the default theme's
tokens as YAML front matter, each matrix class set and single class set as a component (dark values and their
components suffixed `-dark`), and the eight body sections as a snapshot of what the contract draws,
the roster among them with the class sets each component draws, its states and the tokens it owns. It ships
in the package's `files`, so a consumer reads it under `node_modules/@slotform/ui-core/`.

`src/design-md.ts` emits it as a pure function of a resolved theme, so the committed file is checked
against it. `pnpm --filter @slotform/ui-core design-md` writes it, then fails when `design.md lint`
reports an error. The committed file is the emitter's output, never edited by hand.

## In the code

- `packages/ui-core/src/roster.ts`: the layers and `rosterEntries`.
- `packages/ui-core/src/roster/shared.ts`: the shared roster types (`RosterEntry`, the states, token ownership), `build`, the variant props, `TEXT` and the button label class sets.
- `packages/ui-core/src/roster/descriptors.ts`: the descriptors two or more components take (`Run`, `Fact`, `StatusMark`, `ChipMark`, `ChangeKind`, `Drop`, `RouteRegistry`).
- `packages/ui-core/src/roster/<component>.ts`: one component's entry, descriptors, matrices and class sets (`button.ts`, `picker.ts` among them).
- `packages/ui-core/src/descriptors.ts`: the descriptors subpath, re-exports only.
- `packages/ui-core/src/variant-tables.ts`: the shared matrices as data, the chip matrix.
- `packages/ui-core/src/variants.ts`: the cvas, single-class-set constants, `MATRIX_GROUPS` and `matrixClasses`.
- `packages/ui-core/src/list-state.ts`: `splitFacts` and the change and back glyphs.
- `packages/ui-core/src/tokens.ts`: `TONES`.
- `packages/ui-core/src/icon-name.ts`, `packages/ui-core/scripts/icon-name.ts`: the generated `IconName` union and its generator.
- `packages/ui-core/src/design-md.ts`: the `DESIGN.md` emitter.
- `plugins/native-ui/src/ui/lib/facts.ts`: the phone's facts as badges.
